# ПромоЗначки

Рабочая версия: https://promoznachki.ru/. Источник для публикации — ветка `main`.

## Синхронизация с хостингом

13 ноября 2026 года в репозиторий перенесена полная актуальная версия из
`www/promoznachki.ru`: HTML, изображения, стили, скрипты, PHP-обработчик заявок,
`.htaccess` и `.user.ini`. История репозитория сохранена. Внешний FormSubmit
заменён существующим обработчиком хостинга; сохранены Метрика и текущий адрес.

`vercel.json` оставлен для истории и настроек Vercel, но не входит в релиз reg.ru.
PHP-формы работают на хостинге reg.ru; Vercel не является средой проверки отправки.

## Обновление сайта

1. Изменить файлы и отправить изменения в `main` либо создать PR в `main`.
2. Открыть GitHub → Actions → **Site checks and production deployment**.
3. Дождаться успешных `Validate and package` и `Deploy to promoznachki.ru`.

PR запускает только проверки. Push в `main` публикует прошедший проверки архив.
Проверяются HTML, внутренние ссылки, sitemap, JSON-LD, синтаксис JavaScript и PHP,
целостность архива, защита от подмены путей и сценарии отката. Зависимостей npm
и отдельного этапа сборки фронтенда у сайта нет.

В релиз попадают только публичные файлы по списку `scripts/site_rules.py`.
Git, workflow, тесты, документация, ключи и `.env` на сайт не загружаются.

## Устройство деплоя

- Хост: `server122.hosting.reg.ru`, пользователь `u0252265`, SSH 22.
- Корень сайта: `~/www/promoznachki.ru` — ссылка на текущий каталог релиза.
- Релизы и журнал: `~/.deploy/promoznachki/`, вне публичного каталога.
- Скрипты сервера: `deploy_receiver.py` и `site_rules.py` в этом каталоге.
- PHP CLI для проверки на сервере: `/opt/php/8.3/bin/php`.
- Интерпретатор сервера: `/usr/bin/python3.12`.
- Временные ограничения формы находятся вне релизов: `~/.deploy/promoznachki/tmp-forms`.

Новый релиз распаковывается отдельно, проверяются все SHA-256, обязательные файлы
и PHP. После этого ссылка переключается атомарно. Первый запуск сохраняет исходную
папку сайта как `baseline-*`; её не удаляет автоматическая очистка.
После публикации сервер проверяет версию, главную, контакты, sitemap, обработчик и 404.
Затем GitHub сверяет содержимое всех публичных файлов и безопасные ответы формы,
не отправляя письма. При ошибке сервер либо workflow возвращает предыдущий релиз.
Хранятся десять последних релизов, текущая и предыдущая версии и исходный baseline.

Деплои выполняются последовательно, без принудительной отмены выполняющейся
публикации. Устаревший commit пропускается, если перед выкладкой уже появился
новый `main`. Сервер дополнительно блокирует параллельные операции файловым lock.

Файлы на хостинге больше не следует править вручную: следующий push заменит их
версией из `main`. Если аварийная ручная правка необходима, сначала перенесите
её в репозиторий, прежде чем запускать следующую публикацию.

## Откат

GitHub → Actions → workflow → **Run workflow**, ветка `main`, operation `rollback`.
В `expected_release` указать текущий ID из сводки последнего успешного деплоя:
`<40 символов SHA>-<run ID>-<attempt>`. Скрипт вернёт предыдущую версию только если
сайт всё ещё находится на указанном релизе. Это защищает от отката более новой
публикации запоздавшим workflow. После отката согласуйте `main` через `git revert`,
иначе следующий push снова опубликует содержимое `main`.

## Доступ и обслуживание

Секреты Actions: `DEPLOY_SSH_KEY` — отдельный приватный ключ этого сайта;
`DEPLOY_KNOWN_HOSTS` — проверенный публичный ключ SSH-сервера.
Пароль reg.ru в Actions не используется. Ключ на сервере имеет forced command,
принимающий только `deploy`, `rollback` и `status`; интерактивный терминал,
перенаправление портов и SSH-агента отключены. Ключ позволяет публиковать в том
числе PHP-обработчик сайта; считать его полноценным секретом доступа к приложению.

Изменения receiver/rules в Git сами не заменяют доверенный скрипт на сервере:
их нужно отдельно проверить и установить через панель или административный SSH.
После замены ключа сервера обновлять known_hosts следует только после проверки
его отпечатка через доверенный канал, а не отключением StrictHostKeyChecking.

Для смены основной ветки или правил защиты требуется владелец репозитория.
Рекомендуемая основная ветка — `main`, обязательная проверка — `Validate and package`.

## Локальная проверка

Нужны Python 3.12+, Node.js и PHP 8.3+.

```sh
python3 scripts/check_site.py
php -l send-request.php
python3 -m unittest discover -s tests -v
python3 scripts/build_release.py --revision "$(git rev-parse HEAD)" --run-id 1-1
```
